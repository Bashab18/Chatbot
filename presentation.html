RAG Pipeline — Knowledge Retrieval

BM25-based retrieval augments every response with relevant excerpts from the admin-curated knowledge base.

📄

Document Upload

Admin uploads PDF / TXT via multipart form. pdf-parse extracts raw text.

›
✂️

Chunking

Text split into overlapping ~800-token chunks preserving sentence boundaries.

›
🔤

BM25 Tokenise

Each chunk tokenised into word arrays. Token lists stored as JSON in SQLite.

›
🔍

Query & Rank

User message tokenised. BM25 scores all chunks; top-K above min-score returned.

›
🤖

Context Inject

Top chunks prepended to system prompt. Gemini responds grounded in KB content.

Retrieval Controls (Admin-tunable)

  • ragTopK — number of chunks to retrieve (default 5)
  • ragMinScore — BM25 minimum relevance threshold
  • ragWeight — blend KB vs. AI own knowledge (0–100)
  • webSearchWeight — live Google Search grounding
  • Strict KB-only mode refuses off-topic questions

Profile Context Bypass

  • Users with health profiles always get a response
  • Profile data injected even when KB has no hits
  • AI memories extracted from past conversations
  • Google Fit snapshot (steps, HR, weight) injected
  • Personalised answers without KB dependency

Data Layer — SQLite Schema

A single SQLite database (WAL mode) persists all application state — users, conversations, KB, settings, and memories.

👤 users
id TEXT PK
email UNIQUE
name, role TEXT
password_hash bcrypt
login_count, last_login stats
💬 conversations
id TEXT PK
user_id FK → users
title auto-generated
created_at, updated_at epoch ms
📝 messages
id TEXT PK
conversation_id FK → conv
role user | assistant
text TEXT
refs JSON sources
📚 kb_documents
id TEXT PK
name filename
chunk_count INTEGER
added_at epoch ms
🔤 kb_chunks
doc_id FK → kb_docs
doc_name TEXT
text raw chunk
embedding JSON tokens[]
⚙️ settings + memories
settings(key, value) JSON blob
user_profiles health data
user_memories AI-extracted facts
fitness_snapshots Google Fit
Persistence on Render: SQLite database file stored on a 1 GB persistent disk mounted at /opt/render/project/src/backend/data — survives server restarts and redeploys. KB chunks loaded into memory on startup for fast BM25 scoring.
