Introduction · The Problem

The Problem We're Solving

Millions of older adults and health-conscious individuals face a growing gap between the healthcare they need and the information they can access.

🚨 Information Overload

The internet provides billions of health pages — but most are generic, unverified, or contradictory. Patients cannot reliably filter signal from noise.

⏳ Access Barriers

Scheduling a doctor's appointment takes days or weeks. Most questions are routine but still require professional judgment — a gap chatbots can fill.

👴 Older Adult Challenges

Managing multiple conditions, medications, and fitness goals simultaneously is cognitively demanding — especially without a personalized guide.

Features · AI Chat Engine

Feature 1 — AI Conversational Interface

Multi-turn conversations powered by Google Gemini with streaming output and markdown rendering.

Multi-turn Context

Every conversation is stored in SQLite with full message history. The backend sends the last N messages as conversation history to Gemini on every request.

Streaming Responses

The frontend streams tokens as they arrive, providing real-time typing feedback. Users see the response being built character by character.

Suggestion Chips

After each response, context-aware follow-up question chips are generated to guide users through natural health conversations.

Markdown Rendering

react-markdown renders formatted responses with headers, bullet lists, bold/italic text, and code blocks for clinical clarity.

Features · Knowledge Retrieval

Feature 3 — RAG Knowledge Base

BM25-powered retrieval augmented generation grounds every response in admin-curated medical knowledge.

Document Ingestion

  • Admin uploads PDF or plain text files via multipart form
  • pdf-parse library extracts raw text from PDFs
  • Text split into overlapping 400-word chunks (60-word overlap)
  • Each chunk tokenized and stored as JSON in SQLite
  • BM25 index rebuilt in memory on every startup

  • Target chunk size: ~400 words

Tokenization Strategy (embed.js)

  • Lowercase normalization of all text
  • Remove English stopwords (the, a, is, was...)
  • Split on whitespace and punctuation
  • Store as JSON array in kb_chunks.embedding
  • No stemming or lemmatization (simplicity tradeoff)

Security Design

Defense-in-depth approach with authentication, authorization, input validation, and data protection at every layer.

Authentication Security

  • bcryptjs with 10 salt rounds — ~100ms hash computation (brute-force resistant)
  • JWT HS256 with server-side JWT_SECRET from environment
  • 7-day token expiry — balanced security vs UX
  • No refresh tokens — simple forced re-login on expiry
  • Token stored in localStorage (SPA-appropriate)

API Security

  • All data endpoints require valid JWT
  • Admin endpoints require role=admin check
  • CORS: Access-Control-Allow-Origin set to frontend domain
  • Multer limits file size and validates MIME type
  • Parameterized SQL queries — no string concatenation

Data Security

  • Passwords never stored in plaintext — bcrypt only
  • API keys in environment variables, never in code
  • SQLite on persistent disk — not accessible via HTTP
  • Google OAuth tokens stored in DB, not client-side
  • .gitignore excludes .env, /data, /uploads

System Design · Performance

Performance Design

Key design decisions that maximize CIRA's responsiveness despite running on free-tier infrastructure.

In-Memory BM25 Index

The most critical performance decision: all KB chunks are loaded into memory on server startup.

  • Zero disk I/O on every chat request for RAG lookup
  • BM25 scoring is pure JavaScript — sub-millisecond per chunk
  • 10,000 chunks scored in ~5ms (benchmarked)
  • Index rebuilt only on document add/delete

SQLite WAL Mode

  • WAL: writers don't block readers (concurrent chat + admin)
  • Foreign key checks at DB level — no application-layer joins needed
  • better-sqlite3: synchronous, low overhead Node.js binding
  • Single file — no connection pooling complexity

Netlify CDN

  • React build output served from global CDN edge nodes
  • Sub-100ms page load worldwide for static assets
  • API proxy at CDN edge — /api/* → Render backend
  • SPA routing handled by Netlify redirect rules

Architecture · RAG Deep Dive

BM25 RAG Architecture — Deep Dive

The technical foundation of CIRA's knowledge retrieval — BM25 scoring without vector embeddings or GPU requirements.

BM25 Scoring Formula

Score(D,Q) = Σ IDF(qᵢ) × [f(qᵢ,D) × (k₁+1)] / [f(qᵢ,D) + k₁ × (1-b+b×|D|/avgDL)]
k₁ = 1.5 — term frequency saturation
b = 0.75 — length normalization factor
IDF(q) — inverse document frequency
f(q,D) — term frequency in document

Why BM25 over Vector Embeddings?

BM25Vectors
GPU requiredNoOften yes
Latency<5ms50–200ms
CostFreeAPI fees
InterpretableYesBlack box
Medical termsExact matchSemantic only
Setup complexitySimpleComplex

  • 400-word target size — fits Gemini context without wasting space

  • Sentence-boundary splitting — no mid-sentence cuts
  • No minimum chunk size — short documents create fewer chunks
  • Chunk text stored raw — tokenized copy stored separately

Advantage 1 — Grounded, Trustworthy Responses

CIRA's BM25 RAG system ensures every response is anchored to verified medical knowledge — eliminating the hallucination risk that plagues generic AI chatbots.

The Hallucination Problem

Generic AI chatbots (ChatGPT, Gemini without RAG) can confidently state incorrect medical information — a dangerous failure mode in health contexts.

Without RAG (hallucination risk):
"Metformin is safe with grapefruit" ← Potentially dangerous misinformation
With CIRA RAG (KB-grounded):
"According to your medication guide (p.12): Metformin does not have a significant grapefruit interaction, unlike Lisinopril which you also take. Your Lisinopril DOES require avoiding grapefruit."

Why RAG Works in Health Contexts

  • Admin controls exactly what knowledge CIRA can cite
  • Source citations shown for every factual claim
  • Strict KB mode refuses out-of-scope questions entirely
  • Knowledge base updated by healthcare professionals
Clinical Safety: In healthcare, misinformation can cause direct patient harm. CIRA's RAG architecture is specifically designed to prevent the AI from "making things up" — every factual claim traces back to an uploaded document.

Source Transparency
